# Безопасность и следующий этап

Клиентская часть больше не показывает PIN-коды в списке пользователей, экранирует данные из API и ограничивает адрес backend доменом Google Apps Script. Это снижает риск, но не заменяет серверную защиту.

## Обязательные изменения Google Apps Script

1. Не возвращать PIN в ответах `login`, `getUsers` и других методов.
2. Хранить PIN только как стойкий хеш с солью. Для нового PIN использовать криптографически безопасную соль.
3. Выполнять вход через `POST` и возвращать короткоживущий случайный токен сессии.
4. Передавать токен не в URL, а в теле POST-запроса либо в заголовке авторизации.
5. Проверять роль на сервере для каждого действия. Скрытое меню во frontend не является контролем доступа.
6. Ограничить число неудачных попыток входа и вести журнал аудита без PIN и токенов.
7. Не отдавать внутренние модели, операции и цены без проверки сессии.
8. Проверять на сервере формат QR, количества, допустимые статусы и переходы состояний.
9. Защищать операции записи от повторной отправки с помощью idempotency key.
10. Настроить резервное копирование таблиц и периодическую проверку восстановления.

До внедрения серверных сессий приложение следует считать пригодным только для ограниченного внутреннего пилота.
